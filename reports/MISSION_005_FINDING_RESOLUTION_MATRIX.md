## 2. Documented Residual Technical Risks & Architectural Boundaries

1. **Residual Unauthenticated Botnet Clean-IP Budget (`AUD-D1`):**  
   Clean-IP sign-ins (`pairStatus.count === 0`) are isolated from repeat-IP brute force and survive distributed credential-stuffing sprays from `< 120` distinct IPs per `300s` window (`CV_LOGIN_CLEAN_IP_VERIFY_CEILING=120`), while `verifyPasswordAsync` caps global `scrypt` CPU concurrency (`8` active + `32` queued -> `503 auth_busy`) so `/health`, `/readyz`, and authenticated learners remain unaffected. A large residential botnet burning `> 120` unique clean IPs against a single email within 5 minutes can temporarily rate-limit new unauthenticated logins for that single target email for up to 5 minutes until an upstream CDN/WAF Turnstile/WebAuthn challenge is placed in front of `/api/auth/login`.
2. **Deterrent Watermarking Boundary (Honest Non-Claim):**  
   Server-side PDFium rasterisation + burned-in diagonal/micro-banner identity watermarks (`pypdfium2` + `Pillow`) prevent casual redistribution of master PDFs and simple CSS/DOM overlay stripping (`CV-012`, `CV-019`, `SEC-005`), **not** physical camera photography of a screen or adversarial ML inpainting by a determined attacker. No "piracy-proof" claim is made.
3. **Shared Storage Requirement for Multi-Replica Node Deployments:**  
   While relational state, sessions, single-use tokens, and rate-limit buckets share cleanly across multiple stateless API replicas via PostgreSQL 16 (`005-C-2`), master PDF/audio objects in `$CV_DATA_DIR/storage/` require either a shared POSIX volume or an S3-compatible private object adapter before running `> 1` API container replica with live admin uploads.
