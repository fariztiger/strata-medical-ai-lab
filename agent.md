## 12. STANDARD AGENTIC WORKFLOW

Follow this operational sequence:

DISCOVER
  Inspect current project state.
  Identify requirements and dependencies.

PLAN
  Define a bounded objective.
  Define acceptance criteria.
  Identify required resources.
  Estimate costs and risks.

DELEGATE
  Assign independent tasks if useful.
  Prevent agents from editing conflicting files.

RESEARCH
  Gather evidence.
  Verify assumptions.
  Record sources.

IMPLEMENT
  Build working functionality.
  Prefer incremental vertical slices.

TEST
  Execute functional tests.
  Execute security tests.
  Record actual outcomes.

AUDIT
  Review evidence independently.
  Identify remaining defects and limitations.

CORRECT
  Fix verified defects.
  Retest affected functionality.

DOCUMENT
  Update milestones, changelog and reports.
  Record decisions and unresolved issues.

DELIVER
  Present working output.
  Include exact reproduction instructions.
  Disclose limitations and outstanding work.

If testing fails:

- Diagnose the failure.
- Attempt a bounded correction.
- Retest.
- Escalate unresolved blockers.

Avoid endless research, repeated planning,
unbounded retries and unnecessary agent spawning.

## 14. ACCEPTANCE TEST MATRIX

CV-001:
Admin can upload a synthetic PDF.

CV-002:
Original PDF cannot be accessed anonymously.

CV-003:
Authorized student can open assigned material.

CV-004:
Unauthorized student cannot open the same material.

CV-005:
Student A receives a personalized watermark.

CV-006:
Student B receives a different personalized watermark.

CV-007:
Changing client-side identifiers cannot impersonate
another student.

CV-008:
A copied protected page URL does not grant an
unauthorized account access.

CV-009:
Revoked student cannot request new protected pages.

CV-010:
Expired entitlement prevents further access.

CV-011:
Student cannot access admin API operations.

CV-012:
Original PDF is not delivered through browser requests.

CV-013:
Audio access respects student entitlement.

CV-014:
Audit log records relevant access events.

CV-015:
Desktop and mobile layouts work correctly.

CV-016:
No secrets are exposed in frontend bundles or Git.

CV-017:
Existing tests pass following new changes.

CV-018:
Documentation provides reproducible setup steps.

CV-019:
Watermark cannot be removed merely by disabling
a client-side CSS overlay.

CV-020:
Known security limitations are documented.

Record each test as:

- PASS
- FAIL
- BLOCKED
- NOT RUN

Include actual evidence.

Never fabricate test results.

Access revocation cannot erase previously captured
screenshots or previously copied material.

## 16. MEDICAL AI SAFETY

Medical AI research must begin with educational
and research use cases.

Never claim that an unvalidated system can:

- Diagnose epilepsy.
- Diagnose psychiatric disorders.
- Identify psychological trauma from a drawing.
- Determine personality from physical appearance.
- Replace neurological assessment.
- Replace qualified medical practitioners.
- Guarantee treatment outcomes.

KHTP drawings may be used for authorized educational
reflection and research.

Distinguish:

- Direct visual observations.
- Author-provided methodology.
- Research hypotheses.
- Scientifically validated evidence.
- Expert opinion.
- Uncertainty.

Do not present projective drawing interpretations
as established diagnostic facts.

Use synthetic clinical data for initial prototypes.

Any future clinical research involving human participants
requires appropriate consent, governance, ethics review
and expert validation where applicable.

## 27. DEFINITION OF SUCCESS

The initial STRATA proof of concept succeeds when:

- A real document is stored privately.
- An authorized learner can read it.
- An unauthorized learner cannot read it.
- Personalized watermarking is functional.
- Access revocation is functional.
- Security tests produce reproducible evidence.
- The product presents a professional learning experience.
- The system can be demonstrated privately.
- Research findings and limitations are documented.
- Funding and future work are clearly scoped.

The ultimate objective is to demonstrate that
STRATA can transform existing professional knowledge
into practical, secure and responsible digital
educational technology.
